## Problem Statement

The pipeline dashboard computes achievement against targets but renders it as small delta text on KPI tiles ("114.7% of target"). The user wants a presentation-ready visual, modeled on a CRM dashboard reference: a big goal figure with a progress bar, and a "Booked Projects Status" bar. This is the screen shown to management; the numbers must read from across a room.

## Decisions (from the session)

- **D1 — The booked bar measures Won share of pipeline value**: Won SAR value as a share of total pipeline value (Won + open stages), green fill = Won. Chosen over delivery-progress (needs a delivery-status field that does not exist) and over a duplicate goal-percent view. No new data entry.
- **D2 — The goal bar tracks GP only.** The user corrected the recommendation (revenue + GP): "GP only". The 8M SR goal in the reference is a GP goal; HNI manages BD on GP. Revenue keeps living in the KPI tiles.
- **D3 — Approach A: goal band above the KPI strip.** Two new cards above the tiles; the tested KPI strip stays untouched. Ruled out: B "bars inside tiles" (too quiet to be the report-out centerpiece), C "hero band replacing tiles" (restructures tested code, milestone logic not asked for).

## Premises (agreed)

1. Goal widget = Achieved GP vs GP target only. Big figure + progress bar. No revenue bar.
2. Booked bar = Won value share of (Won + open) pipeline value in SAR, from existing deals. Lost and excluded rows (bad value / non-SAR) stay out.
3. **Card 1 respects the Targets panel (period + GP target).** No GP target set: empty state prompting "Set a GP target", never a fake 0%. **Card 2 is a composition snapshot of the current pipeline and deliberately ignores the period**: it answers "how much of my book is already won", computed over ALL non-excluded Won + open rows regardless of date (reviewer finding: `computeTotals` period-filters achieved but not open, so a period-scoped booked bar would mix scopes; a composition snapshot avoids that entirely).
4. Design tokens only, CSS-only bars (no chart library), EN LTR + AR RTL from day one. D1's "green" binds to the `--status-success` token, never a raw hex.

## Recommended Approach (A: Goal band above the strip)

New `GoalBand` markup inside `PipelineTab.tsx` (feature-local; promote to `components/app/` only when a second screen needs it), rendered above `KpiStrip`, `md:grid-cols-2`:

**Card 1 — GP goal**
- Hierarchy top-to-bottom: label row ("GP goal"), value row (big tabular achieved-GP figure, thin separator, "Goal {money(gpTarget)}" muted, percent label at the end), progress bar full-width beneath.
- Progress bar: fill width `clamp(gpTargetPct, 0, 100)%` (negative GP clamps to 0-width fill), brand magenta fill on `surface-2` track. The label always carries the TRUE value at 1 decimal, matching the KPI delta format: "114.7%", "-3.2%". At ≥100% the label uses the success tone (same logic as the KPI delta).
- Accessibility: the bar element gets `role="progressbar"`, `aria-valuemin=0`, `aria-valuemax=100`, `aria-valuenow={clamped}`, and an `aria-label` naming the metric.
- No GP target: empty state text + button that opens the existing Targets panel (`setShowTargets(true)`). Target set but zero Won GP: a real 0.0% bar, NOT the empty state.

**Card 2 — Booked projects**
- One stacked horizontal bar: Won segment (`--status-success` token) + open segment (neutral `surface-2`/line tone), rounded logical corners (`rounded-s`/`rounded-e`), fill anchored to the start side so RTL mirrors correctly.
- Label: "{bookedPct}% booked" as an integer percent; legend "Won (n)" / "Open (n)" with deal counts.
- Accessibility: the stacked bar is one `role="img"` element whose `aria-label` states both segments ("Won SAR X of SAR Y total pipeline, N deals").
- Empty pipeline (denominator 0): neutral empty message in the card, no bar.

**Math**: Card 1 reads `totals.achievedGp`/`totals.gpTargetPct` (period-scoped, as today). Card 2 gets a new pure helper in `pipelineMath.ts`: `bookedShare(rows)` computed from `PipelineRowData[]` directly (not from period-filtered totals): numerator = sum of value over non-excluded `stage === "Won"` rows, denominator = that plus sum over non-excluded open-stage rows; returns `{ wonValue, openValue, wonCount, openCount, pct }` with `pct` an integer, 0 when the denominator is 0, never NaN. Unit tests: empty, Won-only (100), open-only (0), excluded rows ignored, Lost ignored, rounding.

**New i18n keys** (EN + AR, pricing namespace): `goalGp` "GP goal", `goalOf` "Goal", `goalSetTarget` "Set a GP target", `bookedTitle` "Booked projects", `bookedPct` "{n}% booked", `bookedWon` "Won", `bookedOpen` "Open", `bookedEmpty` "No deals in the pipeline yet", `bookedAllTime` "All deals" (caption on Card 2 — it is all-time while Card 1 is period-scoped; the caption stops a viewer cross-comparing the two), `goalAria` "GP achieved versus target" (Card 1 progressbar aria-label), `bookedAria` "Won {won} of {total} total pipeline, {n} deals" (Card 2 aria-label; amounts via `money()`). ARIA labels are localized like any visible string. `bookedShare` gates open rows on `OPEN_STAGES`, same as `computeTotals`.

**Layout order** (explicit): GoalBand → KpiStrip → excluded-note → toolbar → table. The excluded-note keeps its current position directly under the strip.

**States**: no-target empty state, target + zero achieved (0.0%), overachieved (>100% label, capped fill), negative GP (0-width fill, negative label), zero-open (100% booked), empty pipeline, excluded rows out of both cards.

## Not in scope

- Delivery/"Done" tracking per project (would need a real delivery-status field; the sheet's free-text Project Status is not computable). Revisit if the user starts filling structured statuses.
- Quarter milestone ticks (approach C's Gold markers).
- Revenue goal bar (explicitly declined in D2).

## Success Criteria

- With the user's real data and an 8,000,000 GP target: the band shows the achieved-GP figure, the correct percent (matching the Achieved GP tile's delta), and a booked bar whose percent equals Won value / (Won + open value) from the table.
- All Definition-of-Done items in CLAUDE.md, including EN/AR at 4 viewports, empty/overachieved states, tokens only, and e2e coverage (band values react live to a stage change; empty state without target). E2e note: flipping a stage to Won auto-stamps `decidedAt` to today, so the live-reaction test must leave the period unset (or set one covering today) or the achieved figure will not move.
