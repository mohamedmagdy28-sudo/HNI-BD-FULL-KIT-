## Problem Statement

The user wants the pricing/pipeline app as an installable desktop application for Windows (.exe) and macOS (.dmg), fully offline. Driver, verbatim: "for data security and i want it in exe format for windows and similar format for Mac". Installers go to the user plus a few colleagues. The app is already offline-capable at its core (localStorage, no backend); this is a packaging and distribution decision, not an app rewrite.

## Decisions (from the session)

- **D1 — Driver is data security + real installables.** Not PWA, not a hosted site: .exe / .dmg files. The public GitHub Pages deploy is retired once desktop builds work.
- **D2 — Audience: me + a few colleagues.** Unsigned builds with a one-page install note (right-click-Open on Mac, More info → Run anyway on Windows). Code signing deferred until rollout grows (Apple Developer ~$99/yr + Windows cert).
- **D3 — Approach C: Electron now, Tauri later.** Electron ships .dmg + .exe from this Mac today (the only path given the CI constraint). Tauri v2 via GitHub Actions is the upgrade path (10x smaller binaries, signing home) once the user replaces their GitHub token with one carrying workflow scope. The wrapper is disposable; the web app doesn't change between shells, with ONE deliberate exception: the Save-as-PDF button gains a desktop-gated one-click path (below).

## Premises (agreed)

1. Desktop packaging removes the public-website exposure but does NOT add encryption: data sits unencrypted in the app's local storage; theft protection = FileVault/BitLocker + login password. App-level passphrase encryption is a separate future feature.
2. No sync between installs; each machine's data is its own. Sharing = existing Export backup → Import.
3. One-time migration per user: Export backup in the browser, Import in the desktop app.
4. Tajawal must be bundled (the only runtime network dependency today is Google Fonts).
5. Today's builds happen on this Mac: the current GitHub token cannot run Actions workflows, so CI (and Tauri) waits for a token the user creates.

## Recommended Approach (C: Electron now, Tauri later)

**Electron shell over a privileged custom scheme (the load-bearing decision):**
- Do NOT use `loadFile`/`file://`. Register an `app://` scheme (`protocol.registerSchemesAsPrivileged` with `standard: true, secure: true, supportFetchAPI: true` + `protocol.handle` serving files from `dist/` via the `net.fetch(pathToFileURL(...))` pattern, which carries mime types for free), and `loadURL("app://bundle/index.html")`. `registerSchemesAsPrivileged` MUST run before `app.whenReady` (classic first-run failure). This single choice keeps the entire existing app working unchanged: `fetch()` of brand assets in the PPT exporter (fetch rejects file:// URLs), the literal `/brand/...` asset paths in ClientView and the `@font-face` URLs in index.css (absolute paths resolve against the scheme host), and clipboard's secure-context requirement. **No `base` change to the Vite build; the web build is untouched.**
- `electron/main.cjs`: single BrowserWindow; `contextIsolation: true`, `nodeIntegration: false`; all external navigation denied except `shell.openExternal` for http(s). Devtools disabled in packaged builds (enabled via `HNI_DEBUG=1` env for acceptance testing).
- **PDF export upgrade (replaces the browser print-dialog dance):** one minimal preload exposing `window.hniDesktop.savePdf()` via contextBridge → IPC → `dialog.showSaveDialog` + `webContents.printToPDF({ printBackground: true, preferCSSPageSize: true, pageSize: { width: 13.33, height: 7.5 } })`. Units: inches; `preferCSSPageSize` makes print.css's `@page 13.33in 7.5in` the source of truth and the explicit `pageSize` the no-@page fallback. **Caller:** the EXISTING "Save as PDF" button in ClientView feature-detects `window.hniDesktop?.savePdf` — desktop gets the one-click file dialog (no destination-hint toast), web keeps today's toast + `window.print()` path unchanged. `window.print()` stays available for paper in both. (Electron has no Chrome print preview; this is the correct desktop path, not a workaround.)
- Fonts: self-host Tajawal woff2 in `public/brand/fonts/` (the repo's existing font home, beside Myriad Pro) + `@font-face` in index.css; remove the Google Fonts `<link>` AND its two `preconnect` links in index.html. Fixes offline for all targets.
- localStorage persists in the OS userData dir; Export/Import, xlsx import, clipboard TSV, PPT download all standard browser APIs verified available under the app:// scheme.
- **package.json wiring (explicit):** `"main": "electron/main.cjs"`, `productName: "HNI Pricing"`, `appId: "com.hni.pricing"`, `files: ["dist/**", "electron/**"]`; devDeps `electron` + `electron-builder` **pinned to the current 26.x exact version at implementation time** (26-series uses pure-JS resedit; no Wine). `win.signAndEditExecutable` signing off.
- **Icons:** generate `.icns` + `.ico` from the HNI logomark into `electron/icons/`; without them the installer ships the default Electron icon.
- **Targets and names (one scheme, stated once):** macOS `dmg`, **universal** (single file for all Macs) → `HNI-Pricing-<version>.dmg`; Windows `nsis` x64 → `HNI-Pricing-Setup-<version>.exe`. **Known risk:** first NSIS build on Apple Silicon can stumble on binary downloads; fallback target if NSIS fights back: `portable` exe or zip.
- Versioning from package.json. No auto-update; colleagues replace the app when handed a new file.

**Install note (ships with the files, lives at `docs/INSTALL-DESKTOP.md`):** per-OS unsigned-app bypass steps + the one-time Export → Import migration line. Distribution via shared drive or USB only (installers exceed email attachment limits).

**Playwright/e2e:** continues to target the web build; desktop acceptance is the manual success-criteria run (below) with `HNI_DEBUG=1`.

**Tauri later (when the token exists):** GitHub Actions matrix building Tauri bundles from the same dist; signing and auto-update land there. The existing `deploy.yml` (Pages) is deleted — the token's purpose is the future Tauri workflow, not reviving the retired site.

## Not in scope

- Code signing / notarization (revisit at rollout).
- Auto-update infrastructure.
- App-level data encryption (future feature; note it in TODOS).
- Any change to app features, storage schema, or the sheet workflow — EXCEPT the desktop-gated one-click PDF path in the existing Save-as-PDF button (carve-out, agreed in review).

## Success Criteria

- On a Mac with WiFi OFF: the .dmg installs, the app opens, creates a proposal, imports the xlsx, exports PPT (cover art and logos intact — this exercises fetch under app://), saves a PDF via the new one-click path, and shows Tajawal correctly in Arabic.
- The .exe installs and runs the same flows on a Windows laptop (colleague's machine is the test bed).
- Existing browser data lands in the desktop app via Export → Import with identical totals.
- No network requests at runtime (verified in devtools with HNI_DEBUG=1 — note fetch of bundled brand assets via app:// is local, not network).

## Distribution Plan

Direct file handoff (shared drive / USB; too large for email) of `HNI-Pricing-<version>.dmg` and `HNI-Pricing-Setup-<version>.exe`, plus the install note. No store, no CI today; GitHub Actions + Tauri when the workflow-scope token exists.
